## 一、示例 JSON 结构分析

文件：`vocabulary/draw_guess_words_zh-CN_v2.json`（3.3KB，6 个词条，全部为动物/难度 1/zh-CN）

### 1.1 顶层字段

| 字段                   | 类型     | 示例值                   | 语义判定                                             |
| ---------------------- | -------- | ------------------------ | ---------------------------------------------------- |
| `version`              | string   | `"1.0.1"`                | 词库文件自身的版本号（区别于内容哈希版本）           |
| `updated_at`           | string   | `"2026-09-01"`           | 词库最后更新日期（仅元信息）                         |
| `default_time_limit`   | number   | `60`                     | 词条未提供 `time_limit` 时的缺省作画时限（秒）       |
| `default_score_weight` | number   | `20`                     | 词条未提供 `score_weight` 时的缺省计分权重           |
| `category_enum`        | string[] | `["动物","食物",…40 项]` | **分类白名单**：所有词条的 `category` 必须是它的子集 |
| `words`                | object[] | —                        | 词条数组                                             |

### 1.2 词条字段（12 个）

| 字段           | 类型     | 示例                          | 必填判定                                         | 本项目语义                                              |
| -------------- | -------- | ----------------------------- | ------------------------------------------------ | ------------------------------------------------------- |
| `id`           | number   | `1`（全局唯一，1~6）          | 是                                               | 词条稳定 ID（字符串化后进入协议）                       |
| `type`         | string   | `"word"`                      | 是                                               | 词条类型；本项目仅支持 `"word"`，其他值明确报错         |
| `text`         | string   | `"猫"`                        | 是                                               | 答案词面                                                |
| `category`     | string[] | `["动物"]`                    | 是（可为空数组？示例均非空 → 按必填校验）        | 分类标签，必须 ⊆ `category_enum`                        |
| `difficulty`   | number   | `1`                           | 是                                               | 难度 1~5（1 最易），用于选词 UI 徽章与筛选              |
| `hint`         | string[] | `["一种动物", "可以从外形…"]` | 是                                               | **结构化提示列表**：按剩余时间阈值逐条展示给猜词者      |
| `tags`         | string[] | `["动物","短词","易画"]`      | 是                                               | 自由标签（本期仅透传展示，不参与逻辑）                  |
| `lang`         | string   | `"zh-CN"`                     | 是                                               | 语言标识；按配置白名单过滤                              |
| `enabled`      | boolean  | `true`                        | 是                                               | 禁用词条在加载期被剔除，不进入候选池                    |
| `time_limit`   | number   | `45`                          | 是（语义上可缺省 → 缺省用 `default_time_limit`） | **词条级作画时限（秒）**，覆盖房间「作画时间」设置      |
| `score_weight` | number   | `10`                          | 是（可缺省 → 用 `default_score_weight`）         | 计分权重；**语义未明确，本期透传预留**（见 5.4 待确认） |
| `aliases`      | string[] | `["小猫","猫咪","cat"]`       | 是（可为空数组）                                 | **可被判定为正确答案的别称**（规范化后与猜词文本比较）  |

### 1.3 与现状的关键差异

| 维度     | 现状（vocabulary.md）                          | 新 JSON 词库                              |
| -------- | ---------------------------------------------- | ----------------------------------------- |
| 词面     | 纯文本行（891 条）                             | 富对象（示例 6 条）                       |
| 词条 ID  | sha256 前 12 位 hex（`z.string().length(12)`） | 文件内数字 ID → 字符串 `"1"`~`"6"`        |
| 猜词判定 | 仅 `text` 规范化比较                           | `text` + `aliases` 全部可判对             |
| 提示     | 随机逐字揭示遮罩                               | 保留逐字揭示 + **新增结构化提示逐条揭示** |
| 作画时长 | 房间统一 `drawSeconds`                         | 词条 `time_limit` 可覆盖                  |
| 管理维度 | 全选/搜索                                      | 增加分类筛选、难度筛选                    |

## 二、总体设计：Provider 架构（可扩展性核心）

```
                       ┌────────────────────────────────┐
shared/types.ts        │  VocabularyProvider（接口契约） │
VocabularyWord ───────►│   load(): Promise<LoadedVocab> │
VocabularySnapshot     └───────┬---------------┬--------┘
                               │               │
                 ┌─────────────▼───┐   ┌───────▼───────────────┐   （将来）
                 │ JsonFileProvider│   │ SqliteProvider（预留） │
                 │ 本次落地        │   │ 仅需实现同一接口即可接入│
                 └─────────────────┘   └───────────────────────┘
```

- **领域层（GameService/RoundMachine/Snapshot）只依赖接口**，与「词库从哪来」彻底解耦——将来切换 SQLite 时**零改动**领域代码，只新增一个 Provider 实现并在 config 切换。
- 加载期完成：Zod 严格校验 → 规范化/去重 → `enabled=false`/语言过滤 → 内容哈希版本号。**运行期 Store 结构不变**（`items`/`byId`/`version`），下游改动最小。

### 新目录结构（替换现有单文件 `apps/server/src/vocabulary.ts`）

```text
apps/server/src/vocabulary/
├── index.ts               # loadVocabulary()：按 config.vocabulary.provider 选择实现（唯一扩展点）
├── contract.ts            # VocabularyProvider 接口、LoadedVocabulary、VocabularyMeta 共享契约
├── normalize.ts           # 共享纯函数：文本规范化、去重、ID 生成、内容哈希（供各 Provider 复用）
└── json-file.provider.ts  # JSON 文件实现：读取 → Zod 校验（含 category_enum 交叉校验）→ 规范化
```

### 核心接口草案

```ts
/** 词库来源提供者契约：将来 SQLite 只需实现本接口并在 config 中注册 */
export interface VocabularyProvider {
  /** 来源标识（日志/排障用） */
  readonly sourceId: string
  /** 加载并校验词库；失败抛出带中文文案的 Error 阻止启动 */
  load(): Promise<LoadedVocabulary>
}

export interface VocabularyMeta {
  sourceId: string
  fileVersion?: string // JSON 的 version 字段
  updatedAt?: string // JSON 的 updated_at
  categoryEnum: string[] // 分类白名单（透传给管理 UI 做筛选下拉）
  defaultTimeLimit?: number
  defaultScoreWeight?: number
}

export interface LoadedVocabulary {
  words: VocabularyWord[] // 已过滤 enabled=false 与语言白名单、已去重
  version: string // 内容哈希（sha256 前 12 位，随内容变化）
  meta: VocabularyMeta
}
```

## 三、共享协议层改动（`packages/shared`）

### 3.1 `types.ts` —— 富词条模型替换 `VocabularyItem`

```ts
/** 词库词条（富模型）：由 Provider 加载期产出，服务端与客户端共用 */
export interface VocabularyWord {
  id: string // Provider 保证稳定且唯一（JSON 实现 = String(数字 id)）
  text: string // 答案词面
  aliases: string[] // 可判定为正确的别称
  categories: string[] // 分类（⊆ category_enum）
  difficulty: number // 1~5，1 最易
  hints: string[] // 结构化提示（按剩余时间逐条揭示）
  tags: string[] // 自由标签（本期仅透传）
  lang: string
  timeLimit?: number // 词条级作画时限（秒）；缺省用文件 default 或房间设置
  scoreWeight?: number // 词条级计分权重（本期仅透传预留，不参与计分）
}
```

- `VocabularySnapshot` 增加 `categories: string[]`（分类枚举，供管理 UI 下拉筛选），`items` 元素类型换为 `VocabularyWord`。
- `GameView.wordOptions` 扩展为 `{ id, text, categories, difficulty }`（画家选词 UI 显示徽章）。
- `GameView` 新增 `revealedHints?: string[]`（已揭示的结构化提示，随快照按角色下发）。
- **旧 `VocabularyItem` 类型删除**（仓库内一并更新所有引用）。

### 3.2 `schemas.ts`

- 新增导出 `WordIdSchema = z.string().min(1).max(64).regex(/^[A-Za-z0-9:_-]+$/)`：词库 ID 格式与来源解耦（JSON 数字串 / 将来 SQLite 主键串均可）。
- `roomUpdateVocabulary` 处理器的 `ids` 校验从 `z.string().length(12)` 改为 `WordIdSchema`。

### 3.3 协议版本

- 词库 ID 语义、快照结构、wordOptions 结构均变化 → **不兼容变更**：`config/app.ts` 的 `protocolVersion: '5' → '6'`（客户端同仓库同步发布，注册时校验自动生效）。

## 四、服务端改动

### 4.1 `config/vocabulary.ts` 重写（配置单一来源）

```ts
export const vocabulary = {

  filePath: 'vocabulary/draw_guess_words_zh-CN_v2.json',
  encoding: 'utf8' as const,
  minWords: 6, // ★下调：示例词库共 6 条（原 12 将拒绝启动）
  maxWords: 10_000,
  maxWordLength: 24,
  maxAliasesPerWord: 8, // 新增：单词条别称上限
  maxHintsPerWord: 4, // 新增：单词条结构化提示上限
  maxCategoriesPerWord: 3, // 新增：单词条分类上限
  languages: ['zh-CN'], // 新增：语言白名单，其余词条拒绝启动
  difficultyRange: { min: 1, max: 5 }, // 新增：难度合法区间
  deduplicate: true,
  resetWhenExhausted: true,
  useWordTimeLimit: true, // 词条 time_limit 覆盖房间作画秒数（钳制到房间配置区间）
  useWordScoreWeight: false, // ★预留：score_weight 计分语义确认后再启用
} as const
```

### 4.2 `vocabulary/` 目录（替换 `vocabulary.ts`）

- **`contract.ts`**：上文 Provider 接口 + `LoadedVocabulary`/`VocabularyMeta`。
- **`normalize.ts`**（纯函数，可独立单测）：
  - `canonicalWordId(source, rawId)`：生成稳定字符串 ID；
  - `hashWords(words)`：规范化词面+别称拼串后 sha256 前 12 位 → `version`；
  - 去重规则：`text` 规范化重复 → 报错（示例词库不允许重复词面）；别称与别的词条 `text` 冲突 → 仅告警不拒绝（判定时以当前回合答案为准，无歧义）。
- **`json-file.provider.ts`**：
  - Zod schema 严格校验顶层与词条（含 `type==='word'`、`category ⊆ category_enum`、难度区间、语言白名单、字符串长度上限、`enabled` 布尔）；
  - 未提供的 `time_limit`/`score_weight` 回填文件级缺省值；
  - 输出 `LoadedVocabulary`。
- **`index.ts`**：`loadVocabulary(rootDirectory?)` 保留「项目根优先、cwd 回退」的现有路径策略；按 `config.vocabulary.provider` 分发（目前仅 `'json-file'`，未知值抛中文错误）。
- `VocabularyStore` 内存结构保持 `{ items, byId, version }` 并新增 `meta`（快照需用 `categories`）。

### 4.3 `models.ts` / `game-service.ts` / `round-machine.ts` / `snapshot.ts`

| 位置                               | 改动                                                                                                                                                                                                                             |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `models.ts`                        | `GameSecret.answer: VocabularyWord`、`candidates: VocabularyWord[]`；新增 `revealedHintCount: number`（结构化提示已揭示条数，与 `revealedIndices` 并列）                                                                         |
| `game-service.ts` `submitGuess`    | 猜词判定改为：`normalizeAnswer(text)` 与 `answer.text` **及全部 `aliases`** 比较，任一相等即猜中；「很接近」判断对 text+aliases 取最近者                                                                                         |
| `game-service.ts` `pickCandidates` | 逻辑不变（selectedWordIds 池洗牌截取），元素自然变为富词条                                                                                                                                                                       |
| `round-machine.ts` `beginDrawing`  | 作画时长改为 `word.timeLimit ?? room.settings.drawSeconds`，并钳制到 `game.drawSeconds.min/max`（防词库文件写越界值）；`useWordTimeLimit=false` 时行为与现在完全一致                                                             |
| `round-machine.ts` `scheduleHints` | 保留现有逐字揭示；新增结构化提示计时器：沿用 `finalHintThresholds: [0.35, 0.2]`，剩余比例降到阈值时揭示 `hints[已揭示条数]`，受 `settings.progressiveHints` 门控，且揭示条数 ≤ `hints.length`；暂停/恢复沿用现有 hintTimers 机制 |

| `handlers/room.ts`                 | `roomUpdateVocabulary` 的 ids 改用 `WordIdSchema`                                                                                                                                                                                |

`validateBusinessConfig` 的 vocabulary 分支补充新字段校验（minWords ≤ maxWords、difficulty 区间、各上限为正整数）。

## 五、客户端改动

### 5.1 选词 UI（`PhaseOverlay.vue` —— 画家候选词按钮）

- 每个候选词按钮：词面为主文字，右上角/下方新增 **分类徽章**（如 `动物`）与 **难度指示**（如 `★☆☆`，1~5 星按 difficulty 渲染），样式沿用现有黄色按钮 + 行内 Tailwind。

- 新增筛选：**分类下拉**（选项来自 `snapshot.categories`，即文件 `category_enum`）+ **难度下拉**（全部/1~5），与现有搜索框并存（三条件取交集）。

- 搜索匹配范围扩展：`text` + `aliases`。
- 「已选 n / 至少 m」逻辑不变。

### 5.3 对局 HUD（`GameHud.vue` + `useGameHud.ts`）

- 答案遮罩下方新增**结构化提示区**：逐条渲染 `game.revealedHints`（带「提示」前缀小字，淡入动画沿用现有过渡类）；未揭示时不占位。

### 5.4 `config/strings.ts`（UI 文案唯一来源）
