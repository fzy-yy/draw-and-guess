# 分发功能评审加固（slim/full 双包整改）

Status: ready-for-agent

> 来源：对 `8abc326...HEAD`（两笔「feat(分发)」提交）的双轴 code-review 发现清单 + 逐轮 grilling 共识（Q1–Q7，全部由用户拍板）。
> 决策载体：`docs/adr/0034-node-single-file-distribution.md`（本规格实施后需同步该 ADR）。

## Problem Statement

Windows 分发功能（`pnpm package:dist` 产出 slim/full 双 zip）已实现且可用，但评审暴露出让维护者与终端用户不安的问题：

- 一个运行时开关绕开了「部署变量经收口模块治理」的通道，`.env.example` 里查不到它；
- 词库约束的文档表述与实际双目录实现自相矛盾，会误导后续开发者；
- 内置 Node 的下载缓存只判断「文件存在」，一次被中断的下载会留下半截 zip 并**永久命中**，之后每次构建都失败且难自诊；
- 海外 CI runner 默认走国内镜像下载 36MB 运行时，存在拖满超时的不稳定风险；
- 打包脚本用正则反解源码文本取应用版本，格式微调即静默错读；「22」「24」两个基线魔数散落多处；
- `start.cmd` / `使用说明.txt` 的差异化行为（内置版直用 `runtime\node.exe`、精简版检测系统 Node）完全依赖人眼验证，无任何回归测试；
- 构建解压临时目录不清理，每次约 90MB 累积。

## Solution

对已提交的分发功能做一轮**不改变对外形态**的加固：把隐藏开关收编进部署配置治理；把下载完整性从「存在即信任」升级为「同源 SHASUMS 校验 + 损坏自愈」；把打包脚本的脆弱点（版本反解、魔数、解压残留、flag 参数）收敛到单一来源；把 `start.cmd`/说明文本抽为纯函数并纳入既有单测口径；同步修正 ADR/AGENTS/注释中与实现矛盾的表述。slim/full 两包的产物结构、zip 命名、启动语义对用户完全不变。

## User Stories

1. 作为发布维护者，我希望所有能经产物 `data/.env` 生效的运行时变量都收口到部署配置模块并登记进 `.env.example`，以便部署参数有单一可发现的清单、不存在隐藏开关。
2. 作为发布维护者，我希望浏览器自动打开开关沿用现有变量名与「`0` 关闭」语义，以便已在使用的脚本与文档无需变更即继续有效。
3. 作为未来开发者，我希望 AGENTS 词库约束段的表述与「内置目录 + 产物自定义目录」双源实现一致，以便修改词库加载代码时不被「唯一来源」字样误导。
4. 作为发布维护者，我希望内置 Node zip 在被打进 full 包之前经过 sha256 完整性比对，以便损坏或半截的运行时绝不会到达终端用户手里。
5. 作为发布维护者，我希望缓存校验不匹配时自动删除缓存并重下载一次（第二次仍失败才报错），以便曾经中断的构建不需要人工定位与清理缓存。
6. 作为发布维护者，我希望 SHASUMS256.txt 取不到或不含目标 zip 条目时构建立即报错中止（fail-fast），以便校验不会静默退化成「薛定谔的校验」。
7. 作为发布维护者，我希望每次构建用毕的 Node 解压临时目录被清理，以便 `release/.cache/` 不随构建次数累积膨胀。
8. 作为发布维护者，我希望 CI 构建显式使用 Node 官方分发源，以便境外 runner 不受国内镜像稳定性影响。
9. 作为发布维护者，我希望打包脚本直接导入配置包读取应用版本，以便版本字段格式调整时构建要么成功要么编译失败，绝不静默错读版本号。
10. 作为发布维护者，我希望「最低系统 Node 主版本（22）」与「内置 Node 主版本（24）」在代码里有单一来源，以便未来升级 LTS 基线只改一处，脚本模板与打包目标随之联动。
11. 作为测试工程师，我希望 `start.cmd` 与 `使用说明.txt` 的文本由纯函数生成，以便两种包的启动/说明差异在单测里断言，而非每次实跑构建人工核对。
12. 作为测试工程师，我希望 SHASUMS 文本的条目解析是纯函数，以便哈希提取逻辑无需网络即可单测。
13. 作为零依赖终端用户（full 包），我希望分发包内携带的运行时必然是完整校验过的，以便双击 `start.cmd` 的可靠性不因构建环境网络事故而受损。
14. 作为精简包用户，我希望 slim 的系统 Node 检测行为保持不变并被单测锁定，以便这轮加固不改变我已经习惯的启动方式。
15. 作为仓库维护者，我希望 ADR-0034 补充「同源校验不防恶意镜像」的边界与绘图可选原生加速依赖（bufferutil/utf-8-validate）保持外置的说明，以便后续读者准确理解校验的信任模型。
16. 作为代码评审者，我希望所有被改动代码的对应注释同步更新（AGENTS 注释一致性规则），以便不留下说谎的注释。
17. 作为发布维护者，我希望端口探测与正式监听之间的微秒级竞态（TOCTOU）被明确为**已接受的取舍**并在源码注释与 ADR 中记录，以便后来者不把它当作待修 bug 反复评估。
18. 作为后续实现代理，我希望本规格以 `ready-for-agent` 状态存在于议题跟踪器，以便直接按 implement 流程落地而无需再次访谈。

## Implementation Decisions

**范围（grilling Q1）**：评审 11 项发现中除 TOCTOU 重构外全部修复；TOCTOU 以注释 + ADR 记录方式接受。版本保持 `2.5.0` 不升（无 tag、未发布，Q5）；提交拆两笔（Q6）：治理+文档一笔，校验+脚本加固+新缝一笔。

**部署开关收口（Q2）**：`DRAW_GUESS_OPEN_BROWSER` 登记进 `.env.example`，并由服务端部署配置收口模块解析为布尔值（默认开启），服务器入口改读收口结果、不再直读 `process.env`。变量名与「值为 `0` 即禁用」的既有语义保持向后兼容。AGENTS「配置、安全」节的可覆盖变量清单同步加入该名字。

**下载完整性（Q3/Q7）**：构建时从同一镜像、同一版本目录取 `SHASUMS256.txt`；解析出目标 win-x64 zip 的 sha256；对缓存 zip 做流式哈希比对。规则：写缓存后必验；缓存命中先验，不匹配则删缓存重下载**最多一次**，二次仍失败报错；`SHASUMS256.txt` 下载失败或无目标条目 → 立即中止（fail-fast）。`NODE_VERSION` 钉版本路径同样校验。信任边界（同源不防恶意镜像）写入 ADR。

**测试缝（Q4，用户已确认）**：

- 扩展现有构建期纯函数缝（Node 版本解析模块）：新增 SHASUMS 文本解析纯函数；镜像尾斜杠规范化合并为单一实现；新增导出 `MIN_NODE_MAJOR = 22`、`BUNDLED_NODE_MAJOR = 24` 常量，v24 选择正则由常量动态构建，esbuild target 与 `start.cmd` 模板引用常量。
- 唯一新缝：构建期模板纯函数模块（拟名 `dist-templates`，置于版本解析模块旁），把 `start.cmd` 与 `使用说明.txt` 的生成从「写文件」抽为「返回字符串」；落盘仍由打包脚本负责。同时用 `'slim' | 'full'` 联合类型替换布尔 flag 参数（消解 Flag Argument/Primitive Obsession 味道）。
- 不设网络/zip/实跑类新缝：产物行为维持 `package:dist` 人工验证 + CI。

**版本反解修复（发现⑥）**：打包脚本直接 `import { app } from '@draw-guess/config'` 读版本（该 workspace 依赖已存在），删除对配置源码的正则匹配；脚本已运行在 tsx 下，无额外运行时成本。

**杂项**：词库加载器中「结果不依赖遍历顺序」注释修正为「跨目录顺序确定（内置在前）、同目录同名 ID 依赖枚举顺序」的准确表述（发现⑦）；解压临时目录在运行时安装完成后即删（发现⑧）；CI 工作流显式设置 `NODE_DIST_MIRROR` 指向官方 `https://nodejs.org/dist/`（发现④）；`readAppVersion` 报错兜底随直接导入自然消失（发现⑨中 Shotgun Surgery/魔数一并收敛；注意文档中的「22+」字样属人工文案，不参与常量联动）。

**接口与协议**：不改 Socket 协议、不改 DTO、不改 `protocolVersion`、不改两包对外结构与 zip 命名；`pnpm dev`/`pnpm start` 源码模式行为不变。

## Testing Decisions

- 好测试只断言外部行为：纯函数的输入→输出/抛错、生成文本的关键行，不测内部实现细节、不发真实网络请求、不实跑 esbuild/PowerShell。
- 被测模块：
  1. 版本解析缝（扩展）：SHASUMS 文本解析（正常行、多条目取目标、缺条目/格式非法抛错）；镜像尾斜杠合并后的 URL 构建既有用例继续通过；v24 正则随 `BUNDLED_NODE_MAJOR` 常量联动（改常量用例仍绿的构造性断言）。
  2. 模板缝（新）：full 的 `start.cmd` 含 `runtime\node.exe server.mjs` 且不含版本检测分支；slim 含 `where node` 与 `LSS 22`（由 `MIN_NODE_MAJOR` 渲染）；full 使用说明含「内置 Node 运行时」、slim 含安装指引；说明文本含传入的版本号。
- 既有口径复用：文档一致性单测继续校验 AGENTS/README 与代码的交叉引用（本轮会新增/修正 AGENTS 表述，需过该闸）；`test:unit` 全绿为闸。
- 先例：`test/unit/node-dist.spec.ts`、`test/unit/runtime-layout.spec.ts`（同为构建期纯函数、无 IO 的单测形态）；新缝测试与其同目录同风格。
- 最低验证序：`pnpm format && pnpm lint && pnpm typecheck && pnpm build` → `pnpm test:unit` → 本地实跑 `pnpm package:dist`（含一次人为删缓存触发自愈路径、确认解压目录被清理）→ 双 zip 条目复核。

## Out of Scope

- TOCTOU 重构（探测失败重试等）——已明确接受并记录。
- GPG/证书级供应链加固（防恶意镜像）——超出局域网工具定位，仅文档声明边界。
- macOS/Linux 分发、exe/安装器、Node SEA。
- 随包携带 npm/npx/corepack。
- 端到端实跑构建产物（新测试缝为纯函数级）。
- 版本号升级（保持 2.5.0）。
- 评审中两轴均确认无需改动的项（持久化边界、协议、渲染模型等）一律不触碰。
