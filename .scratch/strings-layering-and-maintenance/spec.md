# 规格：文案分层（无障碍 / 可见 / 服务端）与开发期代码库保养

> **Status**: ready-for-agent
> 来源：2026-10-02 用户提出「把 strings 里的无障碍、可见与其他文案分开」+「代码库保养：死代码、冗余、过时注释、去兼容」，经 grill-with-docs 四轮访谈收敛。
> 领域词表：[CONTEXT.md](../../CONTEXT.md)（本规格将新增「可见文案 / 无障碍文案 / 服务端文案」三条术语）。
> 前提：项目处于开发阶段、尚无正式发布用户，因此移除向后兼容措施；运行期健壮性兜底保留。

## Problem Statement

维护者面对两个问题：

1. **文案没有类别边界。** 文案集中在 `@draw-guess/strings` 包，但无障碍文案（`aria-*` 与鼠标悬浮 `title`）、UI 直接可见文案、服务端下发的运行时文案混在同一批按领域划分的对象里。改一处文案时无法按类别审阅：容易把无障碍文案当普通文案改、漏掉某个 `aria-label` 的同步、或让新文案放错语义。随着页面与规则快速演进，文案类别之间持续漂移，维护成本高。
2. **代码库积累了开发期包袱。** 死代码与多余导出（封装边界暴露了从未被引用的类型/常量）、重复定义、只为旧数据或旧版本存在的兼容措施，以及描述已删除功能的过时注释与文档。项目未发布，这些兼容措施没有用户需要保护，属于纯负担；错注释还会误导后续开发。

## Solution

分两阶段（先文案分层、后保养，各自独立验证）：

**阶段一 · 文案分层。** 把 `strings` 重排为两个用途命名空间——`a11y`（无障碍）与 `ui`（可见）——并保持 `serverStrings` 独立顶层。分类口径统一为**按消费位置**：`aria-label/aria-labelledby/aria-describedby` 绑定与原生元素上的 `title` 悬浮绑定属于无障碍；页面渲染文本、输入框 `placeholder`、Toast/请求提示与元信息属于可见。全量迁移调用点、删除旧 key、不加兼容别名。新增一条源码扫描测试作为整层契约的护栏，防止以后分类回混。

**阶段二 · 开发期保养。** 删除死代码与多余导出、统一重复定义；清理过时/错误/复述型注释与文档；移除真正的向后兼容措施（旧迁移链、旧词库列的兼容夹具、值级布尔兼容），但保留运行期健壮性兜底（断线重连、Worker 降级、非法推送重同步、剪贴板 legacy 降级等）。

## User Stories

1. 作为维护者，我想要无障碍文案集中在 `strings.a11y`，以便一次性审阅全部 `aria-*` 与悬浮提示、不遗漏。
2. 作为维护者，我想要可见文案集中在 `strings.ui`，以便调整界面措辞时只面对可见文本，不被无障碍与运行时文案干扰。
3. 作为维护者，我想要 `serverStrings` 维持独立顶层，以便区分「服务端下发、经事件/ack 到达界面」的文案与客户端本地文案。
4. 作为维护者，我想要文案分类口径写死为「按消费位置」，以便新增文案时有唯一判断标准，不再凭感觉归类。
5. 作为维护者，我想要悬浮 `title` 归入无障碍、`placeholder` 归入可见，以便口径符合「悬浮即无障碍辅助」的直觉且输入占位仍算可见界面。
6. 作为维护者，我想要同一条文本既作可见标题又作悬浮提示时拆成两个 key，以便两个命名空间各自纯净、护栏不误报。
7. 作为维护者，我想要跨类共享的纯函数放在独立内部模块而非任一类，以便两个命名空间不互相依赖。
8. 作为维护者，我想要旧的扁平 key（如 `strings.game.penAria`）被彻底替换为带类别路径的 key 且不留别名，以便代码里只有一种正确写法。
9. 作为维护者，我想要一条源码扫描测试在「`aria-*`/原生 `title` 绑定了 `strings.ui` 的文案」时报失败，以便分类回混在 CI 就被拦住。
10. 作为维护者，我想要该扫描测试用「原生标签小写、Vue 组件 PascalCase」区分原生 `title` 与组件 `title` 属性，以便把可见的分节标题误判成无障碍。
11. 作为维护者，我想要删除 `strings` 包内已无引用的类型导出（如 `Strings`/`ServerStrings`）与其它确定无人引用项，以便包表面只保留真实使用的东西。
12. 作为维护者，我想要去掉 `apps/*` 中「导出了但从未被 import、仅在模块内使用」的多余 `export`，以便模块边界反映真实依赖。
13. 作为维护者，我想要合并被内联复制两份的协议枚举（`joinPolicy`），以便协议常量只有一个来源。
14. 作为维护者，我想要把快照里内联的成员判定改为走既有具名谓词，以便成员事实保持单一口径。
15. 作为维护者，我想要数据库迁移链压平为单条最终 schema 基线，以便不再维护「建旧表/旧列再删」的空转历史。
16. 作为维护者，我想要旧版本数据库在启动时以清晰中文错误提示删除本地库，以便迁移语义明确、不静默带病运行。
17. 作为维护者，我想要旧词库列的兼容夹具与相关断言被移除，以便测试只针对当前词库结构。
18. 作为维护者，我想要布尔环境变量只接受 `true`/`false`，以便配置契约简单明确。
19. 作为维护者，我想要在收窄布尔取值的同时同步更新配置文档与样例，以便文档与校验不打架。
20. 作为维护者，我想要保留剪贴板的 legacy 降级，以便在局域网 HTTP（非安全上下文、`navigator.clipboard` 不可用）下复制仍可用。
21. 作为维护者，我想要保留断线重连、Worker 失败降级、非法推送重同步等兜底，以便「去兼容」不误伤当前功能必需的健壮性。
22. 作为维护者，我想要修正与代码不符的注释（声称迁移 `avatarColor`、声称针对「旧客户端」、仍写速度奖/顺序奖、难度星级、结构化提示等），以便注释不再误导。
23. 作为维护者，我想要修正已过时的文档描述（对局布局、协议号、ADR 状态与已废弃 ADR 的引用），以便文档与代码一致。
24. 作为维护者，我想要在领域词表新增「可见文案 / 无障碍文案 / 服务端文案」三条术语，以便议题、测试与注释使用统一语言。
25. 作为维护者，我想要两阶段各自跑通格式、Lint、类型检查、构建与相关测试，以便重构与清理不引入回归。
26. 作为玩家（间接受益），我想要界面文案与无障碍标签始终成对、不缺失，以便使用读屏或悬浮提示时获得一致信息。

## Implementation Decisions

**文案分层**

- 目录即类别、文件即领域：无障碍文案与可见文案各自按领域分文件；`serverStrings` 与 `serverErrorMessages` 保持独立顶层文件。
- 导出形状：`strings = { a11y: {...}, ui: {...} }`；调用点变为 `strings.ui.<领域>.<key>` 或 `strings.a11y.<领域>.<key>`。
- 分类口径（按消费位置）：`aria-label/aria-labelledby/aria-describedby` 绑定与原生元素 `title` 绑定 → `a11y`；渲染文本、`placeholder`、Toast/请求提示、元信息（标题/描述）→ `ui`。
- 双用途文案：同一条文本若既作可见标题又作悬浮/aria 名称，拆成两个 key——可见的留在 `ui`，在 `a11y` 新增同名语义 key（文本可相同）。
- 跨类共享的纯函数（如延迟封顶）放独立内部模块，两个命名空间都从它导入，互不依赖。
- 全量迁移所有消费点（stores、composables、handlers、组件、测试），删除旧 key，不留兼容别名。

**护栏**

- 新增源码扫描单测（见 Testing Decisions 接缝 A）。规则：凡 `aria-*` 绑定与原生元素 `title` 绑定引用的文案必须来自 `strings.a11y.*`；`strings.ui.*` 不得出现在这些绑定中。
- 区分方式：属性所在元素标签为小写（原生 HTML）时 `title` 视为无障碍；标签为 PascalCase（Vue 组件）时 `title` 视为组件属性（可见），不纳入扫描。

**开发期保养**

- 迁移压平：把历史迁移合并为单条最终 schema 基线，schema 版本归 1；启动时检测到更高版本（旧库）直接抛中文错误并提示删除本地 `game.db`。
- 旧词库夹具：移除刻意保留的旧列与对应兼容断言，测试只覆盖当前词库结构。
- 布尔配置：收窄为大小写不敏感的 `true`/`false`；移除 `1/0/yes/no/on/off` 等兼容写法，同步更新配置校验、测试与文档/样例。
- 死代码：删除确定无人引用项；去掉 `apps/*` 内多余 `export`；统一被复制的 `joinPolicy` 枚举；快照内联成员判定改走谓词。不删 `packages/shared` 经 `export *` 暴露的公共 API 面，也不删协议「只写不读」字段。
- 保留项：剪贴板 legacy 降级（局域网 HTTP 非安全上下文的必要路径）、断线重连/宽限、Worker 失败降级、非法推送重同步、多候选路径探测、本地存储逐字段防御校验、预留诊断导出。
- 注释与文档：修正与代码不符的注释；更新对局布局描述；把文档中的协议号订正为当前值；补正已废弃 ADR 的状态行；把源码中对已废弃 ADR 的引用改指现行 ADR。不新增 ADR。

## Testing Decisions

- **好测试的标准**：只验证外部可观察行为——文案类别契约、迁移结果、配置校验结果；不测内部实现细节，不逐组件重复断言。
- **接缝 A（新增，最高层）**：一条源码扫描单测，枚举 `strings.a11y`/`strings.ui` 的导出与源码中的 aria/title 绑定，断言分类规则。先例：现有文档一致性测试对仓库源码的扫描式校验。
- **接缝 B（复用）**：以临时 SQLite 库验证迁移——空库迁移得到最终 schema；模拟旧版本库时迁移抛中文错误。先例：现有持久化单测的临时库用法。
- **接缝 C（复用）**：以配置校验纯函数验证布尔取值——仅 `true`/`false` 通过，其余（含旧兼容写法）报错。先例：现有配置校验单测。
- **接缝 D（无新接缝）**：死代码与多余导出由类型检查与 Lint 把关；注释/文档由文档一致性测试与人工核对。
- **全量验证**：两阶段各自执行 `pnpm format && pnpm lint && pnpm typecheck && pnpm build`，并运行相关 unit/component/integration 测试。

## Out of Scope

- 不新增 ADR（仅更新领域词表与既有文档）。
- 不移除协议「只写不读」字段、不改协议版本。
- 不删 `packages/shared` 的公共 API 导出面。
- 不删预留的诊断导出。
- 不合并客户端与服务端刻意各自维护的成员事实谓词。
- 不做任何界面视觉或交互改动。
- 不重构与本次无关的长组件。
- 不整理 `.scratch/` 下的历史工单。

## Further Notes

- **执行顺序**：阶段一（文案分层）完成后立即做阶段二（保养）；两块各自验证，避免一次改动过大难以定位问题。
- **迁移压平的前置动作**：需要删除本地运行期数据库文件（`apps/server/data/game.db`）。执行前会单独确认；不与用户已有其它数据混淆。
- **双用途文案的取舍**：拆成两个 key 会带来少量文本重复，但换取两个命名空间语义纯净与护栏可判定；这是有意接受的成本。
- **保留剪贴板 legacy 的理由**：局域网访问是纯 HTTP，属非安全上下文，现代 Clipboard API 不提供，`execCommand` 降级是唯一复制途径，属健壮性而非兼容措施。
- **CONTEXT.md 术语**：本规格批准后在词表中新增「可见文案（ui strings）」「无障碍文案（a11y strings）」「服务端文案（server strings）」三条，并顺带修正词表中过时的浮层面板描述。
- **盘点依据**：本规格的范围来自三份并行代码库盘点（死代码/冗余、兼容措施、过时注释与文档），高置信项直接纳入，低置信/有行为影响的项已在 Implementation Decisions 中标注为保留或出界。
