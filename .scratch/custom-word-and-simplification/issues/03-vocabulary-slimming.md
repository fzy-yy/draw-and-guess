# T03 · 词库瘦身：删除难度、可绘制性、难度级配置与提示

**Status**: ready-for-agent
**Blocked by**: 02

> 依据：`.scratch/custom-word-and-simplification/spec.md`「批次 ② 词库瘦身」。

## 目标

词条只保留词面、分类、别称与启用状态；词库包元数据只保留名称、描述、版本、更新时间与分类枚举。磁盘上的旧词库文件继续可用，多余列被忽略而不报错。

## 范围

- **共享契约**：词条 DTO 删除难度、可绘制性、提示、派生时限与派生权重；词库包元数据 DTO 删除难度枚举、可绘制性枚举、可绘制性说明、难度级配置；保留分类枚举、别称、启用。
- **词库 Provider**：改为只读取需要的列；删除难度枚举、可绘制性枚举、难度区间、提示长度、难度级配置与难度枚举严格互相覆盖、可绘制性说明等全部加载期校验，以及难度级配置的解析与派生。
- **服务端私有配置**：删除难度区间与提示长度上限。
- **候选抽词**：删除按目标难度分层与难度接近度兜底的逻辑，只保留「同一回合候选尽量来自不同分类」这一条偏好；`optionCount` 语义不变。
- **公开配置与 UI**：删除难度/可绘制性相关的展示配置；删除难度星级组件及其全部引用。
- **客户端词库弹窗**：删除难度、可绘制性、时限、权重四列与两个筛选下拉；保留词面、分类、别称、启用与分类筛选；词库查询/选择组合式函数同步收敛。
- **客户端选词卡**：不再显示难度星级。
- **测试夹具**：测试词库生成器与两条 fixture 管道改为不再产出难度、可绘制性、提示与难度级配置；受影响的单元/组件/集成测试同步。
- **文档**：词库字段说明的改动由 T05 统一收口，本工单只保证代码与测试自洽。

## 非目标

- 词库 `.db` 文件的删列与重建（另开任务）。
- 分类与别称的删除（保留）。
- 「词条数不足 60 无法开局」这条门槛（保留）。

## 验收

- [ ] 词条与词库包元数据的 DTO、Schema、Provider 中不再出现难度、可绘制性、难度级配置、提示、派生时限与派生权重。
- [ ] 旧词库文件（仍带这些列）可以正常加载并开局，不报错、不要求换库。
- [ ] 词库弹窗只剩词面/分类/别称/启用四列与分类筛选；难度星级组件及其全部引用被删除。
- [ ] 同一回合抽到的候选词在可能的情况下分类互不相同。
- [ ] 对局流程（抽词、选词、作画、猜中、结算）在假运行时与组件用例中均不受影响。

```bash
pnpm format && pnpm lint && pnpm typecheck && pnpm build

```

## 备注

加载期校验被删除后，旧词库里的残留列处于「无人校验」状态，这是刻意接受的过渡态；不要顺手加上「发现多余列就报错」的检查。
