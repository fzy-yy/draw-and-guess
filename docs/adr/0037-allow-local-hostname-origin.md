# 0037 来源放行面增加「服务器自己的名字」，只为支持用计算机名访问

**状态**：已采纳

## 背景

同一局域网的玩家习惯用计算机名访问服务（`http://my-pc:5174`，macOS/Linux 上更常见 `<名字>.local`）。但来源判定此前只放行回环、私网 **IP 字面量**（契约见 [0036](0036-origin-private-ip-literal.md)），域名形态一律被拒——而这些请求的静态资源不受来源限制，于是现象是**「页面能打开、Socket 一直连不上」**，与反向代理漏传 `Host` 的症状完全同形，玩家与临时运维都极容易误判成防火墙问题。

## 决策

启动装配时枚举**本机自己的名字**并注入来源判定，命中即放行：

- 操作系统报告的主机名（`os.hostname()`）；
- 其 `.local`（mDNS/Bonjour）形态；
- 报告值是 FQDN（Linux/macOS 常见）时，再补**首个标签**（短名）及其 `.local` 形态——短名是同一台机器的另一种写法，也正是玩家实际输入的写法。

比对规则：

- **完整相等**（大小写不敏感），不做前缀或后缀匹配——`my-pc.evil.com`、`evil-my-pc` 一律落空；
- 名单在启动时取一次（属于 OS 事实，生命周期内不变），不在每个请求里问操作系统。

## 为什么这条规则不会被 DNS rebinding 利用

DNS rebinding 的前提是**攻击者掌握被访问名字的解析权**：他把自己域名的 A 记录指向受害者内网地址，于是浏览器发出的 `Origin` 与他控制的域名一致。而本规则比对的是「**名字是否等于这台服务器自己的名字**」——这个名字的解析权在内网自己的解析体系（NetBIOS/mDNS/内网 DNS），不在攻击者手里。攻击者把 `evil.com` 指向内网 IP 得不到任何好处：`evil.com` 不等于本机名，仍被拒。

这也是它区别于「Origin 与请求 `Host` 同名」那种规则的地方：后者的比对目标由**请求方**决定，攻击者可以两者一起伪装，所以没有采纳。

## 后果

- 局域网里 `http://<服务器计算机名>:5174` 与 `http://<计算机名>.local:5174` 可以直接连上（此前是「页面能开、连不上」）。
- 放行面新增了一类**域名**：名字等于本机名即放行。风险接受在内网可信的前提下——名字本身不是秘密，攻击者猜到它也没有额外收益（他猜不到也拿不到玩家的身份令牌，令牌只在原站点的存储里）。
- **FQDN 首段短名**的派生（`mbp.example.com` → 放行 `mbp`）在字面上略宽于「等于本机名」，但在「hostname 返回 FQDN」的机器上，短名才是玩家真正会输入的写法；这是刻意保留的偏差。
- 用**别人的**计算机名、自定义主机名或任意域名访问，仍然被拒；排障时按 IP 访问始终可用（启动横幅播报的就是 IP）。
