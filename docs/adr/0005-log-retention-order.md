# 0005 日志保留按创建时间删最旧，不按文件名排序

- 状态：已采纳

## 背景

日志文件名是 `app-<秒级时间戳>.log`，同秒内多次启动会追加 `-2`、`-3`… 数值后缀。
原实现按文件名**字典序**排序后删除最旧，而字典序里 `-10.log < -2.log`：
同一秒内重启超过 10 次后，会把后创建的文件当成「更旧」删掉，反而保留了更早的文件。

## 决策

- 保留策略改为按**文件创建时间**升序排序（`birthtimeMs`，极少数文件系统不支持时回退 `mtimeMs`）；
- 同秒文件名冲突时用递增后缀规避覆盖，但**排序不再依赖文件名**；
- 排序只针对 `*.log`，其余文件不参与清理。

## 后果

- 「保留最近 N 个」在任何重启频率下都成立，不再误删新日志；
- 代价：依赖文件系统的创建时间；不支持 `birthtime` 的平台会退化为修改时间——
  对本场景（每次启动写一个新文件）语义等价。

## 关联

- 代码：`apps/server/src/logging/file-logger.ts`（`prepareLogDir`）
- 配置：`.env` 的 `LOG_MAX_FILES`、`LOG_ENABLED`
