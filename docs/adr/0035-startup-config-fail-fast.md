# 0035 启动期配置「写法或取值不对即中止」，不静默取默认值

**状态**：已采纳

## 背景

`.env` 是这台机器上唯一的部署覆盖入口（`HOST`/`PORT` 与日志开关等）。旧实现的失败姿态是「能解析就解析、解析不了就当没写」：

- 配置文件整份读取失败被 `catch {}` 吞掉——配置根本没读到，进程却按默认值照常启动；
- 文件带 UTF-8 BOM 时首个键名会变成 `\uFEFFHOST`（键名前多出不可见字符），那一行配置**静默失效**。而「记事本另存为 UTF-8」与 PowerShell 5.1 的默认写法都会写出 BOM，是 Windows 上的常见来源；
- `PORT` 走 `Number()`：`1e3`、`0x1502`、`5174.0` 都能解析成整数并绑到别的端口；
- `HOST` 不校验形态：非法值要等绑定阶段才抛 getaddrinfo 错误，运维只能对着 DNS 报错猜自己写错了什么；
- 布尔变量把一切非开族值按「关」处理：`LOG_ENABLED=ture` 会**无声关闭全部日志**。

共同结果：**配置写了却没生效，且没有任何可观察迹象**——局域网场景下表现为「地址连不上」「一直没有日志」，排查成本全花在猜上。

## 决策

显式写下的配置只要写法或取值不对，一律在启动期抛出「实际取值 + 成因」的中文错误并终止启动：

1. 配置文件首三字节是 UTF-8 BOM → 中止（不静默剥离），文案点名成因与「另存为 UTF-8 无 BOM」的修正办法；
2. 配置文件读取 / 加载失败（权限不足、路径是目录等）→ 中止，文案带系统错误码；
3. 布尔变量只接受开族（`1/true/yes/on`）与关族（`0/false/no/off`）两组等价写法，大小写与空白不敏感；族外值中止并点名变量；
4. `PORT` 只接受纯十进制正整数（1～65535）、`HOST` 只接受 IP 字面量或 RFC1123 主机名；「写法不对」与「超出范围 / 形态不对」分别是两种可读成因。

「未设置」（键缺失或纯空白）不在此列——那本来就是「取默认值」的正常路径，不属于配置错误。

## 后果

- 「配置没生效」从静默变成一条可读的启动错误。代价是写错配置的机器**起不来**——这是刻意取舍：局域网派对游戏宁可当场报错，也不要带着半生效的配置继续跑（`PORT=1e3` 这类误配恰恰最难从现象反推）。
- 历史的 `DRAW_GUESS_OPEN_BROWSER=0` 等关闭写法由关族保持兼容；带 BOM 的配置文件不再被加载，需按提示重存一次。
- 严格校验的边界（哪些写法被拒）都写在纯函数的错误信息里，并由 `test/unit/deployment-config.spec.ts` 与 `test/unit/startup-environment.spec.ts` 锁定；改动判定面必须同步用例。
