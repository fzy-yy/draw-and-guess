# 0051 · 房间规则弹窗平铺两列栅格，区间字段一律用下拉

**状态**：已采纳

- 来源：2026-10-02 界面走查（登录页图标与房间规则弹窗两处标记）。

## 背景

规则弹窗把字段分进「基础设置 / 高级设置」两个可收纳 `<details>`：基础区 2 列、高级区 3 列，
字段实际只有 13 项。收纳带来的不是省空间（弹窗高度本来就写死 `h-[82cqh]` 并可滚动），
而是额外一次点击与一处「哪些算高级」的语义分歧；两区列数不同、开关又挤在单格里，视觉参差。

区间字段（每人作画次数 1–5、选词时间 10–30 秒、候选词数量 2–5）用的是滑块，档位分别只有
5 / 5 / 4 档，拖动滑块选 5 个离散值既占纵向空间，又难以精确落点；「选词时间」还与
「选词阶段限时」开关构成一对联动（开关关闭时滑块禁用、显示「不限时」），两个控件讲一件事。

## 决策

1. **取消收纳分组**：字段一次性平铺进两列等宽栅格，行高统一（`auto-rows-[minmax(8cqh,auto)]`，
   桌面基准下 6 行等高），弹窗仍固定 `h-[82cqh]` + 表单区滚动。
2. **排序规则：下拉字段在前、复选框字段在后，同类同行**（6 个下拉占前 3 行、6 个复选框占后 3 行）。
   同类成对可避免「矮复选框被拉伸到下拉行高」；复选框在固定行高内保持自身高度并垂直居中。
3. **区间字段改用下拉**：档位由配置的 `min/max/step` 展开（`packages/config/src/game.ts`），
   一次列出全部取值；删除滑块原语 `RuleSliderField`（设置页的音量等滑块是另一个组件，不受影响）。
4. **「选词时间」两个协议字段合并为一个下拉**：选项为「不限时 / 10…30 秒」，选「不限时」即
   `allowChooseTimeLimit=false`，选具体秒数即置 `true` 并写入 `chooseSeconds`；切回「不限时」
   保留上次秒数（协议字段与摘要口径不变，见 ADR-0045）。
5. **最大玩家数的下拉直接过滤掉低于「当前占席数」的档位**（占席口径同服务端 `occupiesSeat`，
   客户端新增同名谓词，见 ADR-0023），因此删掉「当前成员数以下的值不可保存」提示：
   非法值不可选，不需要事后拒绝。

## 后果

- 弹窗只剩一个栅格，扫读顺序与配置文件的字段顺序一致；字段增减只改一处模板。
- 6 行固定行高在 82cqh 里留出底部空白——这是「行高不随内容拉伸」的代价，换来行行齐平。
- 区间字段的取值被限制在「配置里的档位」：将来若要任意值输入，下拉需要换成数字输入而非滑块。
- 新增共享原语时不能再假设「区间 = 滑块」；`RuleSelectField` 是规则弹窗里唯一的区间控件。
