# 0036 Origin 放行的私网来源只认 IP 字面量，不认域名前缀

**状态**：已采纳

## 背景

局域网部署下，浏览器来源校验（HTTP CORS 与 Socket.IO 握手共用）按「本机 / 私网」放行。其中私网判定与启动横幅的地址播报共用 `isPrivateIpv4`，而它是**前缀匹配**（`/^10\./`、`/^192\.168\./`、`/^172\.(16-31)\./`）。

只按前缀判定时，`10.attacker.com`、`10.0.0.20.attacker.com`、`192.168.1.1.evil.com` 这类**域名**同样命中前缀，于是被当作局域网来源放行。

攻击路径（DNS rebinding）：恶意页面把自有域名解析到受害者所在内网的地址；受害者浏览器打开该页面后，页面用该域名发起请求——`Origin` 与请求目标是同一个域名，而浏览器实际连到的是内网里的本服务。来源校验此时放行，恶意页面即可与本服务建立 Socket.IO 连接（枚举房间、占用席位与连接额度）。它拿不到玩家身份令牌（令牌只在原站点的存储里），但仍可把服务当成免费的公共后端使用。

## 决策

私网来源必须先过 `isIPv4` **字面量闸**，再判定是否属于 RFC1918：

```ts
isIPv4(hostname) && isPrivateIpv4(hostname)
```

规则保持「只放行字面量」的单一取向：「域名前缀像私网」不构成放行理由——地址是否在私网，只能由地址本身证明。

## 后果

- 正常用法不受影响：`http://192.168.1.20:5173`、`https://10.0.0.20` 等本来就是字面量（横幅播报的局域网地址也都是字面量，与放行面同源）。
- 想用**主机名**访问的诉求（如 `http://my-pc:5174`）在本决策下不在放行面内，需要单独评估——**后续**：[0037](0037-allow-local-hostname-origin.md) 以「只放行服务器自己的名字」的方式满足了该诉求，本决策对私网来源「只认字面量」的要求保持不变。
- 判定收紧后，任何以「前缀匹配」为由放宽私网判定的改动都必须重新过一遍本决策。
