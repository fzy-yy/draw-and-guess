# 领域文档

工程技能在探索代码库时如何消费本仓库的领域文档。

本仓库为**单上下文**布局：根目录一份 `CONTEXT.md` + 根目录 `docs/adr/`
（编号 ADR，每条含背景/决策/后果；`AGENTS.md` 仍是项目约束的第一入口，二者互补）。

## 探索前先读这些

- 仓库根目录的 **`CONTEXT.md`**（术语表/领域词汇，惰性创建）
- **`docs/adr/`**：读与本次改动区域相关的 ADR

若这些文件尚不存在，**静默继续**：不要特意指出缺失，也不要建议提前创建——
`/domain-modeling`（经 `/grill-with-docs` 与 `/improve-codebase-architecture` 进入）
会在术语或决策真正确定时惰性创建。

## 使用词汇表中的词汇

当输出（议题标题、重构提案、假设、测试名）指称某个领域概念时，使用 `CONTEXT.md`
中定义的术语；不要漂移到词汇表明确回避的同义词。
如果需要的概念还不在词汇表里，那是一个信号：要么你在发明项目不用的语言（重新考虑），
要么存在真实空缺（记下来留给 `/domain-modeling`）。

## 标记 ADR 冲突

若输出与既有 ADR 矛盾，要显式点破而不是悄悄覆盖：
「与 ADR-0010（绘图历史只增不删）矛盾，但值得重新讨论，因为……」。
